# 上传客户 ID 批量补全省市

入口：应用启动器 → 客户省市批量补全。需要分配“客户地址批量补全管理员”和“客户地址补全记录查看”权限集，并具备客户记录及开单省市编辑权限、名称/街道/国家/城市/省份/经营范围读取权限。联网还需要 DeepSeek_Core_Business 对应外部凭据主体权限。

1. 准备 UTF-8 单列 CSV，第一行 `Id`，之后每行一个15或18位 Salesforce 客户 ID。每次最多300条，文件最多20KB。
2. 上传文件仅预检，列出可处理、重复、无效和跳过原因，不发起查询、不修改客户。
3. 检查后点击“开始处理符合条件的客户”。提交时重新检查客户条件及记录编辑权限，复用已有待处理请求，避免重复联网。
4. 页面每10秒刷新；来源、识别方式、省市和失败原因逐条显示。关闭页面不取消任务，稍后在“客户地址补全记录”查看。
5. 失败或未匹配不会自动反复调用。修正资料或核查后，仅重新上传需要重试的ID。

仅经营范围非空且开单省份或城市为空的客户进入队列。开单街道为空仍可按客户名称联网查询。优先本地地址识别；只补空省市，保留现有城市，不修改街道和客户编码。识别期间客户资料变化会跳过旧结果。批量入口不会扫描未上传的客户，但共享队列仍会处理触发器已产生的其他请求。

后台逐条执行，300条的实际完成时间取决于联网响应及 Salesforce 异步调度，不能保证固定分钟数。正常处理不依赖页面持续打开；建议按 ADDRESS-ENRICHMENT.md 配置队列兜底调度。

示例模板：`templates/address-account-ids.csv`（只有表头，请粘贴真实ID后上传）。不要把客户ID文件提交到Git仓库。

本入口随现有 SmartX Customer Credit Code 的下一版本发布。安装生产包与执行生产批量任务是两件事；安装本身不会批量处理历史客户。

导出候选客户可使用 `WHERE (BillingState = null OR BillingCity = null)`。经营范围是否非空仍由程序检查（长文本字段不宜直接用于SOQL筛选）。分类门类不是程序必备条件。省市任一缺失都可入队；只有省份时不会据此猜测普通省份的城市。
