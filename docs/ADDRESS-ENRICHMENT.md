# 开单省市自动补全

适用 zihao 沙盒，生产部署需另行操作。本功能不生成或修改客户编码，也不批量扫描历史客户。

## 触发条件

Account 新建或更新，`jingyingfanwei__c`（经营范围）有值且 `BillingState`（开单州/省）为空。
更新时仅客户名称、经营范围、开单街道、国家、城市、州省发生变化才创建请求。
同一客户同一输入指纹不重复查询；失败不会自动重复联网。修改相关地址资料后可重新触发。

## 处理流程

保存后异步处理，刷新客户页面查看补齐结果。首先根据现有 `SccRegionRule__mdt` 的省、市和分号分隔别名识别街道开头。
全称、常见行政后缀简称可识别；城市唯一时反查所属省。直辖市省市使用同名。
道路、大厦名称不当作行政区划；省市冲突和无法唯一匹配时转联网，不凭重名区县推断。
只明确识别省份时可以仅填省份，城市留空。现有城市和识别结果冲突时不写入。

未识别时使用 `DeepSeek_Core_Business/responses` 发起一次带 web_search 的请求，45 秒超时，不进行格式重试。服务端实际搜索次数由接口控制，不能保证其遵守 max_tool_calls 参数。
tool_choice 使用 auto 以允许返回最终答案，同时必须检查响应中有已完成的 web_search_call；没有实际搜索记录的模型回答不采用。该网关 required 模式实测可能连续搜索却不返回最终文本，因此不使用。
发送客户名称、街道、国家、现有城市以及最多1500字符经营范围，仅查询省市。
要求客户全名一致（忽略英文大小写）、主体确认、有来源且省市通过配置核验；否则保留空值并记录原因。
写入前重新锁定读取客户，任何相关资料变化都使旧请求失效。
只补空的 `BillingState`、`BillingCity`，不改国家、街道、经营范围和编码。

## 配置覆盖

2026-09-22 zihao 有369条有效省市规则，覆盖大陆31个省级行政区。
没有完整区县库，也不覆盖港澳台和国外省市，不能承诺识别任意地址。
现有国家非大陆或查询省市不在规则库时保留空值供人工核对。
别名调整继续维护省市自定义元数据；不能将区县重名当作唯一城市别名。

## 记录与后台任务

对象 `SccAddressLookup__c`，标签“客户地址补全记录”，权限集“客户地址补全记录查看”。
状态：PENDING待处理、RUNNING处理中、COMPLETED成功、NO_MATCH无法可靠匹配、SKIPPED输入过期、FAILED异常。
来源：STREET街道规则、WEB联网。保留联网来源、填入省市及处理说明。
记录默认私有，用户查看自己创建的请求，管理员可统一查看。

触发器批量持久化请求，每事务最多启动一个队列。先独立事务领取请求，再执行可能的联网调用，防止重复领取和提交前调用错误。
每15分钟的 `SccAddressSweep` 只接续待处理请求，不扫描历史客户、不重试失败联网；超过1小时未完成的运行记录标记失败。
Named Credential 的外部凭据主体须允许执行用户使用；权限不足会记入失败说明。

部署清单：`manifest/address-enrichment.xml`。新对象首次部署后需赋予查看权限，才可通过用户 API 查询其字段。
此功能依赖现有 Account.jingyingfanwei__c；该经营范围字段由原业务维护，不重复创建。
本次源代码新增组件尚未创建新的正式软件包版本。

- 临时客户真实触发：街道“广东省深圳市南山区科技园”写入广东省/深圳市。
- 临时公开企业客户真实联网：北京百度网讯科技有限公司，无开单街道，成功写入北京市/北京市；来源保存在地址补全记录（北京市公共资源交易服务平台、百度隐私FAQ）。
