# 0.3 版本生产安装准备

使用既有 SmartX Customer Credit Code 解锁包升级，不需要卸载0.2版本。本版包含原客户编码功能，以及省市自动补全、最多300条ID的CSV批量入口、查询来源和可筛选排序的处理原因。

## 安装前

- 目标为 SmartX 生产环境；检查已有 Account.jingyingfanwei__c 经营范围字段。它是目标组织依赖，不在包内新建。
- 确认 DeepSeek_Core_Business 命名凭据的端点、认证以及执行用户的外部凭据主体权限已配置；服务需支持当前 Responses/web_search 请求。密钥不随包迁移。
- 已安装旧包时直接升级。保留六类序列的现有计数；不要卸载旧包或重置序列。省市/行业等自定义元数据随包升级，应先备份生产自行维护的规则并在升级后核对。

## 手动安装

在 RELEASE.md 的正式生产安装链接中核对名称和0.3.0.1版本，选择“仅为管理员安装”。等待安装成功后按以下步骤配置。发布状态以 RELEASE.md 为准。

1. 给负责批量操作的用户分配“客户地址批量补全管理员”（SccAddressBulkAdmin）及“客户地址补全记录查看”（SccAddressAuditViewer）。普通查看人员仅分配后者。操作者还需可编辑相关客户及开单省市、可读取输入字段，并具备联网凭据主体权限。
2. 从应用启动器打开“客户省市批量补全”；可将该标签和“客户地址补全记录”加入现有应用导航。
3. 如需队列中断后的兜底调度，管理员手动执行 scripts/apex/schedule-address-enrichment-production.apex。该脚本仅接受已核实的 SmartX 生产组织ID，并幂等创建每小时0、15、30、45分的四个任务。不要在生产执行名称不含 production 的沙盒初始化脚本。打包过程不会替用户执行生产调度脚本。
4. 先上传5～10个生产客户ID，核对预检及查询结果，再按每份最多300条提交。上传仅预检，点击“开始处理”才创建请求。
5. 在“客户地址补全记录 → 地址补全处理结果”按原因筛选。历史终态记录的原因仍为空，不会因升级自动重查或回填。

触发条件：经营范围非空且省或市任一为空；新建/相关字段变化或显式批量提交时运行。先识别街道，不能补齐则联网；已有字段不覆盖，冲突/证据不足/查询期间资料变化会记录原因。安装本身不扫描历史客户，但安装后相关客户编辑会触发自动补全。

本次验证在 zihao 进行；生产的权限、凭据、规则差异需要安装后按小样本核验。序列值、客户和审计数据均不随软件包复制。
